# VoiceBridge web setup

The browser studio uses the existing Supabase and ElevenLabs backend. The sandbox preview is a UI-only mode: recording and local playback work, but translation, sign-in, English reading and sending are unavailable until the services below are configured. Microphone access requires HTTPS (or localhost) and permission.

## Local development

1. Install Node 22 and FFmpeg including ffprobe. Run `npm install` in the repository root.
2. Create a Supabase project, enable email/password auth, add your website URL to the Auth site and redirect URLs, and apply **all** files in `supabase/migrations` in timestamp order. The private `voicebridge-private` bucket and service role permissions are required. Never expose a Supabase secret to the browser.
3. Copy `.env.example` to `apps/api/.env` and fill `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `ELEVENLABS_API_KEY`, and `FFMPEG_PATH`. Use an ElevenLabs plan with Dubbing v2 and Scribe v2 batch access. ElevenLabs may charge for dubbing and the transcript-edit instruction; this project makes no claim about cost or language availability.
4. Start `npm run dev:api` and `npm run dev:worker` in separate terminals. For the web proxy, create `apps/web/.env.local` with `API_PROXY_TARGET=http://127.0.0.1:8080` (or export that variable in the terminal running the web command). Start `npm run dev:web`, then open http://localhost:3000. If using a remote preview, permit the public preview hostname in the auth redirects.
5. Sign up, confirm your email if required, and sign in. Record or upload your own audio, select a language, confirm permission and translate. The result is generated by the dubbing provider using your recording as reference, not a guarantee of identical voice or accuracy. Check it before sending.

The API and worker need access to the same configuration and FFmpeg/ffprobe. The API enforces the configured file-size and duration limits. Transcripts/audio are processed by ElevenLabs; audio and jobs are stored in the private Supabase bucket/database. Incoming English reading uses ElevenLabs Scribe v2 with a natural-language translation edit. Its output may contain mistakes and translation can fail independently; the original transcript is shown when available. Incoming notes are not auto-imported: export or save an audio message from the messaging app, then upload it with permission. There is no personal WhatsApp inbox integration.

## Optional native messaging

Only explicitly authorized application accounts may use the deployment's shared provider credentials. Set `VOICEBRIDGE_ALLOWED_USER_IDS` to a comma-separated list of Supabase Auth user UUIDs in `apps/api/.env`; this is server-side configuration and is **not** a browser key. Do not run this shared-credential model as an unrestricted public service. Restart the API after changing settings. The user must confirm that they listened and that the recipient consented.

* WhatsApp: configure `WHATSAPP_ACCESS_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, and `WHATSAPP_GRAPH_API_VERSION` (for example `v23.0`, use an active Meta API version). The sender must be a registered WhatsApp Business Cloud API number. Personal WhatsApp Messenger cannot be linked for programmatic sending via this integration. Business messaging rules, consent and the customer-service window apply; audio cannot be sent outside eligible sessions unless Meta's policies allow it. The existing adapter uploads OGG/Opus and sends `audio.voice: true`. The recipient's number must include the country code. Meta accepting a message is not proof of delivery.
* Telegram: configure `TELEGRAM_BOT_TOKEN`. The recipient must have started that bot and supply their numeric chat ID. The website calls Telegram `sendVoice`, not `sendAudio`. This prototype does not implement a bot onboarding flow to discover chat IDs. Be careful to enter the right ID.

The authenticated API verifies ownership of each completed translation and saves a reservation with a unique request key before calling the provider. A provider timeout or error is marked **unknown**, and the app does not automatically retry; ask the recipient before trying again to avoid duplicates. Provider acceptance is not the same as delivery. Provider webhooks, delivery receipts, multi-tenant per-user credentials, automated Telegram linking, and personal WhatsApp access are not implemented. Generic Share audio uses the device share sheet and **may create an audio attachment rather than a native voice bubble**.

## Production

`npm run build:web` and `npm run build:api`; serve the website through the Fastify API with `WEB_DIST_PATH` pointing to `apps/web/dist` if needed. Run the dubbing worker separately and install FFmpeg/ffprobe in both containers. Use HTTPS and configure CORS, auth redirects, database backups, logging redaction, rate limits, storage retention/deletion policies, provider quotas and monitoring before deploying. This is a prototype, not a production security or delivery guarantee. Do not expose Supabase service-role, ElevenLabs, WhatsApp, or Telegram secrets to the browser or commit them.

## Verify before launch

Use `docs/CORE_ACCEPTANCE.md` for the explicit end-to-end acceptance checklist and remaining release gates. Automated tests mock provider calls; they do not establish that your provider plan, browser, worker, database or real messaging accounts work. Each Dubbing project may incur a provider charge. After an interrupted provider creation, check your ElevenLabs dashboard before resubmitting; the worker avoids an automatic duplicate when creation is ambiguous.
